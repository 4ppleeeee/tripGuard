# 分析上报文档

## 目标
根据用户提供的上报文档或相关代码文件，将上报事件、参数、触发时机整理为标准需求文档格式，帮助开发者快速理解并实现上报逻辑。

---

## 触发条件
用户提供以下任意一种输入时触发本 skill：
- 上报文档（Markdown 格式）
- 上报相关代码文件路径
- 页面名称或功能模块名称
- 上报事件关键词

---

## 执行步骤

### Step 0：模式判断

```
CHECK: 当前页面目录下是否存在 diff/ 子目录，且其中包含 {页面名下划线}_diff.md？
  ├── YES → ✏️ 迭代模式：先读取基线上报文档（`{page}_report.md`），再结合 diff 需求分析变更部分
  └── NO  → 🆕 新建模式：全量生成完整上报文档
```

**迭代模式判断逻辑：**
- 读取基线上报文档，将其中已有的上报事件视为「已知信息」
- 对照 diff 需求文档，判断哪些上报事件是新增的、哪些是修改的、哪些是删除的
- **若 diff 需求中上报无任何变化**：输出 `{page}_report_diff.md`，内容写「上报需求保持原样，无变更」，不重新生成完整上报文档
- **若有变化**：只输出变更部分，使用下方 diff 上报文档模板

---

### Step 1：解析输入，确定分析范围

**若用户提供上报文档：**
- 直接分析文档内容，提取上报事件、参数、触发时机等信息

**若用户提供代码文件路径：**
- 读取相关代码文件，分析上报实现逻辑
- 查找上报事件定义、参数传递、触发时机等关键代码

**若用户提供页面名称或功能模块：**
- 在代码库中搜索相关页面或模块的上报实现
- 分析该页面/模块的所有上报事件

**若用户提供上报事件关键词：**
- 在代码库中搜索相关上报事件的定义和使用
- 分析该事件的参数、触发条件和实现逻辑

---

### Step 2：获取上报相关信息

调用 `codebase_search` 或 `grep_search` 工具，根据输入类型搜索：
- 上报事件定义（position、action_id 等）
- 上报服务类（如 `*ReportService`、`*ReportHelper`）
- 页面 ID 定义（如 `BeaconPageDefine`）
- 上报参数定义和传递逻辑

---

### Step 3：结构化分析输出

按以下标准需求文档格式输出，**严格参照如下模板**：

---

```markdown
# {页面名称}上报需求描述文档

## 1. 说明
- 本文档定义{页面名称}的页面级与组件级上报需求，用于重写实现。
- 除表中业务参数外，公共基础参数由上报框架自动附加（如 `page_id`、`ref_page_id`、`page_step`、`time` 等）。

## 2. 页面级上报

| 上报描述 | 事件id | 上报参数（包含取值逻辑） | 触发时机 |
|---|---|---|---|
| 页面进入 | `page_visit` | `event_type=1`；`page_id={PageId值}` | 页面对用户可见时触发（进入页面或页面回到前台） |
| 页面退出 | `page_visit` | `event_type=2`；`page_id={PageId值}`；`page_live_time=页面停留毫秒数` | 页面不可见时触发（返回、跳转其他页、切后台） |

## 3. 组件级上报（点击/聚焦）

| 上报描述 | 事件id | 上报参数（包含取值逻辑） | 触发时机 |
|---|---|---|---|
| {组件1描述} | `user_action` | `position="{position值}"`；`action_id={action_id}`；`action_object="{对象值}"`；`type={附加参数JSON}`（无值则空串） | {触发时机描述} |
| {组件2描述} | `user_action` | `position="{position值}"`；`action_id={action_id}`；`action_object="{对象值}"` | {触发时机描述} |

## 4. 组件曝光上报
- {曝光上报说明，若无则写：本页当前需求不定义独立组件曝光事件（`user_exposure`）。如后续需要曝光统计，可按组件补充 `position` 并统一接入 `user_exposure`。}
```

---

**填写规则：**

1. **页面级上报**：
   - 进入事件固定为 `event_type=1`，退出事件固定为 `event_type=2`
   - 退出事件需附加 `page_live_time=页面停留毫秒数`
   - `page_id` 填写该页面的实际 PageId 值

2. **组件级上报**：
   - 事件 id 统一为 `user_action`
   - `action_id=1000001` 表示聚焦类事件，`action_id=1000002` 表示点击类事件
   - `action_object` 通常为 `"-1"`（无具体对象时）
   - `type` 字段为 JSON 格式，记录当前状态快照（如当前昵称、性别等），无值时用空串
   - 若无 `type` 附加参数，则该列不填写 `type` 字段

3. **组件曝光上报**：
   - 若文档/代码中有曝光事件，按组件逐一列出，事件 id 为 `user_exposure`
   - 若无曝光需求，统一写明说明语

---

### Step 4：保存输出文档

**新建模式**：将分析报告保存为 Markdown 文件，与需求文档、协议文档、截图放在同一目录下：

- **目录结构**：`docs/component/{模块名}/{页面名驼峰}/`
- **文件命名**：`{页面名下划线}_report.md`

**迭代模式**：将 diff 上报文档保存到 `diff/` 子目录：

- **目录结构**：`docs/component/{模块名}/{页面名驼峰}/diff/`
- **文件命名**：`{页面名下划线}_report_diff.md`
- **若上报无任何变化**：文件内容写「上报需求保持原样，无变更」，不重新生成完整上报文档

**迭代模式的 diff 上报文档模板：**

```markdown
# {页面名称}上报变更文档（diff）

> **关联需求：** {TAPD 需求标题}（ID：{需求ID}）
> **基线上报文档：** [查看完整上报文档](../{页面名下划线}_report.md)

## 变更概览

| 变更类型 | 上报描述 | 说明 |
|---------|---------|------|
| 新增 | {上报描述} | {说明} |
| 修改 | {上报描述} | {变更说明} |
| 删除 | {上报描述} | {删除原因} |

## 新增上报事件

| 上报描述 | 事件id | 上报参数（包含取値逻辑） | 触发时机 |
|---|---|---|---|
| {新增上报描述} | `{event_id}` | {参数说明} | {触发时机} |

## 修改上报事件

| 上报描述 | 事件id | 变更后上报参数 | 变更说明 |
|---|---|---|---|
| {修改的上报描述} | `{event_id}` | {变更后参数} | {变更说明} |

## 删除上报事件

- {上报描述}：{删除原因}
```

**执行步骤：**
1. **查找匹配目录**：扫描 `docs/component` 下的目录，根据分析对象判断是否已有对应的页面文件夹
2. **新建模式有匹配**：将文档放入对应页面目录，文件命名为 `{页面名下划线}_report.md`
3. **新建模式无匹配**：根据分析对象创建新的文件夹，再将文档放入其中
4. **迭代模式**：在原页面目录下创建 `diff/` 子目录（若不存在），将文档保存为 `{页面名下划线}_report_diff.md`

> 文件命名示例：
> - 新建：`docs/component/drama/findDramaPage/find_drama_page_report.md`
> - 迭代：`docs/component/drama/findDramaPage/diff/find_drama_page_report_diff.md`

## 示例调用

**用户输入：**
> 帮我分析一下编辑资料页的上报文档

**执行流程：**
1. 解析输入 → 确定分析对象为"编辑资料页"
2. 调用 `codebase_search` 搜索编辑资料页相关上报代码
3. 调用 `grep_search` 查找上报事件定义和参数
4. 按标准需求文档模板输出分析报告
5. 将报告保存为 `docs/component/user/editPage/edit_page_report.md`

**用户输入：**
> 分析这个上报文档：[文档内容]

**执行流程：**
1. 解析文档内容，提取关键信息
2. 补充搜索相关代码实现（如有代码库）
3. 按标准需求文档模板输出分析报告
4. 根据文档内容确定模块和页面名，保存报告
