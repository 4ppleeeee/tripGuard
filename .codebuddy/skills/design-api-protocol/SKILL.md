# 接口协议设计

## 目标
根据评审通过的需求文档，自动分析业务数据流，生成规范的接口协议文档，包括接口定义、字段说明、数据类型和错误码。

---

## 触发条件
用户提供以下输入时触发本 skill：
- 评审通过的需求文档（`docs/component` 目录下的 `.md` 文件路径或文档内容）

---

## 输入

| 参数 | 说明 | 是否必须 |
|------|------|----------|
| 需求文档 | 评审通过的需求文档，包含页面清单、组件清单、交互逻辑、数据需求 | ✅ 必须 |
| 基线协议文档 | 已有页面的现有协议文档（`{page}_protocol.md`） | 迭代模式必须 |

---

## 模式判断

```
CHECK: 当前页面目录下是否存在 diff/ 子目录，且其中包含 {页面名下划线}_diff.md？
  ├── YES → ✏️ 迭代模式：读取基线协议 + diff 需求，只输出变更部分
  └── NO  → 🆕 新建模式：全量生成完整协议文档
```

---

## 输出

接口协议文档（Markdown 格式），包含：
- 接口列表总览
- 每个接口的详细定义（请求/响应数据结构、字段说明、错误码）
- 接口依赖关系说明

---

## 执行步骤

### Step 0：模式判断

先检查当前页面目录下是否存在 `diff/` 子目录，且其中包含 `{页面名下划线}_diff.md`：

- **新建模式**：diff 目录或 diff 需求文档不存在，直接执行 Step 1
- **迭代模式**：diff 目录及 diff 需求文档均存在，先读取基线协议文档（`{page}_protocol.md`），再结合 diff 需求分析变更部分

---

### Step 1：读取需求文档

1. 读取用户指定的需求文档（通常在 `docs/component/{模块名}/{页面名驼峰}/{页面名下划线}.md`）
2. 提取以下关键信息：
   - **页面生命周期**：进入页面时需要加载哪些数据
   - **互动组件**：哪些交互会触发网络请求（如点击按钮、下拉刷新、上拉加载等）
   - **动态组件**：哪些组件的内容来自后端接口数据
   - **接口异常 UI 变更**：需要处理哪些异常场景

---

### Step 2：分析数据流，识别接口需求

根据需求文档，识别出所有需要的接口：

1. **数据加载接口**：页面进入时需要加载的数据
2. **用户操作接口**：用户交互触发的接口（如提交、删除、收藏等）
3. **分页加载接口**：列表类页面的翻页接口
4. **刷新接口**：下拉刷新对应的接口

对每个接口提取：
- 接口用途（对应需求文档中哪个交互或数据展示）
- 需要的请求参数（从交互逻辑和页面上下文推导）
- 需要返回的数据字段（从动态组件和 UI 展示需求推导）

---

### Step 3：参考项目现有接口模式，优先复用存量接口

#### 3.1 读取存量接口清单

**必须先读取** `docs/api-command-list.md`，该文档整理了项目中所有已有的业务接口命令字，按业务域分类。

对 Step 2 中识别出的每个接口需求，逐一在存量清单中查找：

- **能复用**：直接引用已有命令字（Req/Rsp 类名），在协议文档中标注 `[复用已有接口]`，并注明来源业务域和所在模块。
- **不能复用**：确认无匹配后，按项目命名规范新增命令字，在协议文档中标注 `[新增接口]`。

**复用判断标准**：
1. 接口的**业务语义**与需求一致（如"拉取用户基础信息"可复用 `stGetUserReq`）
2. 接口的**请求参数**能满足当前场景（如已有接口支持按 uid 查询，当前需求也是按 uid 查询）
3. 接口的**响应字段**覆盖当前页面所需的数据（允许只使用响应中的部分字段）

**不应强行复用的情况**：
- 业务语义相近但请求参数结构差异较大
- 响应字段缺少当前页面必需的核心数据，且无法通过扩展字段补充
- 已有接口属于不同业务域，复用会造成跨域耦合

#### 3.2 了解项目接口规范

1. 搜索 `shared/src/commonMain` 中已有的 Repository 文件，了解接口调用模式
2. 查看已有的 Wire PB 请求/响应类型命名规范
3. 参考 `WireSendExt.kt` 中的 `Message.send()` 扩展函数的使用方式
4. 了解项目中 PB 命令字的推导规则（请求类名去掉 `st` 前缀和 `Req` 后缀）

> 本项目使用 **Wire + Protocol Buffers** 作为网络通信协议，不使用 REST JSON API。接口协议以 PB Message 定义形式输出。

---

### Step 4：生成接口协议文档

**🆕 新建模式**：按以下结构生成完整协议文档（格式见下方模板）。

**✏️ 迭代模式**：先读取基线协议文档（`{page}_protocol.md`），再结合 diff 需求文档，判断：
- **无接口变化**：直接输出 `{page}_protocol_diff.md`，内容写「接口协议保持原样，无变更」，不重新生成完整协议

### Step 5：保存接口协议文档

**新建模式**：将文档保存到与需求文档相同的目录中：

- **目录结构**：`docs/component/{模块名}/{页面名驼峰}/`
- **文件命名**：`{页面名下划线}_protocol.md`

**迭代模式**：将 diff 协议文档保存到 `diff/` 子目录：

- **目录结构**：`docs/component/{模块名}/{页面名驼峰}/diff/`
- **文件命名**：`{页面名下划线}_protocol_diff.md`
- **若协议无任何变化**：文件内容写「接口协议保持原样，无变更」，不重新生成完整协议

**执行步骤：**
1. 扫描 `docs/component` 下的目录，判断是否已有对应的页面文件夹
2. 新建模式有匹配：将文档放入对应页面目录，文件命名为 `{页面名下划线}_protocol.md`
3. 新建模式无匹配：根据需求所属模块和页面创建新的文件夹，再将文档放入其中
4. 迭代模式：在原页面目录下创建 `diff/` 子目录（若不存在），将文档保存为 `{页面名下划线}_protocol_diff.md`

> 文件命名示例：
> - 新建：`docs/component/user/editPage/edit_page_protocol.md`
> - 迭代：`docs/component/user/editPage/diff/edit_page_protocol_diff.md`
